当前 AJ Customer API 已提供提单阶段、总件数、渠道件数、渠道交接时间、POD，以及航司建档、航司到达、清关和 AJ 到仓时间。以下内容需要 AJ 补充真实数据，才能完成 Omniship 剩余字段的自动同步。

| 数据需求 | Omniship 对应字段 | 需要说明的业务口径 |
| --- | --- | --- |
| 已扫描数量 | `receivedCount` | 已扫描的唯一货物数量。重复扫描是否去重，数量单位是否与 `shipment.packages` 一致 |
| 入库数量 | `inWarehouseCount` | 累计已入库数量，或当前库存数量。请明确退仓、出库后该值是否减少 |
| 放行数量 | `releasedCount` | 已放行的唯一货物数量，以及部分放行、扣留、销毁时的处理 |
| NOA 实际时间 | `noaAt` | NOA 对应业务事件和发生时间 |
| 实际提货时间 | `collectionAt` | 从航司或前一仓库提货的实际时间，区别于到达 AJ 仓库时间 |
| 实际扫描时间 | `scannedAt` | 扫描开始、首次扫描或全部扫描完成，请明确采用哪个事件 |
| 逐包裹编号 | `parcelUnitNumber` | 能与客户 Pre Alert 文件中的 Parcel Unit Number 对应的稳定编号 |
| 逐包裹状态 | `parcels[].status` | 完整状态代码枚举及业务含义，包括查验、放行、扣留、销毁、入库和出库 |
| 包裹入库及出库标记 | `parcels[].inbound`、`parcels[].outbound` | 每个标记对应的实际业务事件，纠正或撤销时如何返回 |

可以扩展现有 `GET /shipments/{awb}` 响应，也可以新增只读接口。请提供最终请求路径、认证方式和响应示例。新增字段名由 AJ 确定，Omniship 将依据确认后的文档映射。

如果包裹接口分页，请提供下一页标识、总条数、完整性标记，以及同一次拉取期间保持数据一致的方法。还需要说明接口返回完整快照还是增量数据，包裹被删除、拆单或移交其他提单时如何标识。

数量为 `0` 应代表确认的零数量。暂时未知或无法提供的数据应明确返回空值或省略字段。请区分尚未发生与明确撤销，避免客户端将暂缺数据解释为删除已有记录。

时间请沿用带英国时区偏移的 ISO-8601 格式。当前字段的映射按 AJ 文档原意执行。

| 当前 AJ 字段 | Omniship 显示 |
| --- | --- |
| `milestones.record_created_airline_at` | 航司建档时间 |
| `milestones.status_1_at` | 航司到达时间 |
| `milestones.pick_up_at` | AJ 到仓时间 |
| `milestones.customs_clearance_at` | 清关时间 |
| `vendors[].handed_over_at` | 渠道交接时间，用于计算整票出库完成时间 |

数量口径以 AJ 渠道件数合计与本地提单 `pieces` 一致为校验条件。有交接时间的渠道视为该渠道全部件数完成交接，出库数量为这些渠道件数之和。渠道合计等于本地件数且全部交接后，整票出库完成时间取最后一个渠道交接时间。AJ 顶层 `packages` 若与已核对一致的渠道合计不同，保留数量差异提示，但不阻止按渠道同步；本地原始 `pieces` 不变。渠道合计与本地也不一致时，暂停数量与出库完成时间更新并转管理员核查。没有渠道数据时，仅在顶层 `packages` 与本地件数一致时同步应收总量，不推算出库数量和时间。
