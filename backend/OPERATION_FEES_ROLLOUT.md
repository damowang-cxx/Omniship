# 申报行操作费上线说明

## 行为

- 新上传：现有税费另加数据行数 × EUR 2.00。选择与供应商规则相同的工作表，固定跳过第一行及全空行；不去重、不按税费规则筛选，公式和数值 0 计入。
- 历史提单：不自动收费。管理员在提单详情点击“补扣申报行操作费”后收费；余额不足不扣款。已收费或已撤销的操作费不可再补扣。
- 税费、操作费独立记账和退款；整单取消只退尚未退款的费用。已被发票引用的账务不能直接删除。
- 两类费用分行开票；原有其他费用只随税费行计入一次。历史发票金额和明细快照不重新计算。
- 目的港 LHR 使用所选 Supplier 已发布版本的独立配置：每票 EUR 清关费、该客户的 GBP/kg 报价，以及匹配提单前三位的 GBP 货站附加费。附加费可以是固定金额或按重量段收费；重量段匹配时向上取整到整公斤。一个前三位前缀只能配置一次，未匹配时附加费为零。LHR 不收 Supplier 税费和申报行操作费；其他机场仍按上述现有规则收费。GBP 与 EUR 分别从各自余额扣除，分别开票。未配置该 Supplier 或该客户的报价时，LHR 上传失败且不扣款。

## 发布顺序

1. 备份数据库及上传文件，暂停上传、补扣、充值、退款、取消提单和开票写入，并停止旧后端进程。
2. 在 backend 目录使用项目虚拟环境执行 `python -m alembic upgrade head`，确认版本为 `202611100001`。
3. 发布新后端，再发布经 `npm run build` 构建的前端；两者一起上线后恢复写入。
4. 核对首批上传：预估税费、操作费、合计与实际两笔扣款及最终余额一致；非计税机场仍收取操作费。
5. 核对首笔历史补扣：审计事件 `retroactive_operation_fee_deduction` 包含数量、单价、金额和余额，重复请求返回 409；撤销后详情状态为已撤销且没有补扣按钮。
6. 管理员在 Supplier 页面、Published configurations 下方的独立“LHR 扣费配置”区域选择 Supplier，设置清关费、客户每公斤报价、货站附加费前缀和重量段并保存。保存会发布新的 Supplier 版本。上线前先配置所有要上传 LHR 的客户；未配置客户会被阻止上传。附件中的机场货站价格仅作为配置示例，不会自动导入。
7. 由管理员为测试客户分别充值 EUR 和 GBP，核对首笔 LHR 上传的清关费、重量费、匹配的货站附加费、两个余额、三笔独立账务记录和分别生成的 EUR/GBP 发票。

迁移给历史扣费及退款补充税费类型，给历史发票行补充名称及 EUR 币种，给历史客户新增 GBP 0 余额；不生成扣款、不改历史 EUR 余额和金额。

## 验证

常规测试：在仓库根目录执行 `.venv/Scripts/python -m pytest backend/tests`，前端目录执行 `npm test`、`npx tsc --noEmit --incremental false`、`npm run build`。

PostgreSQL 专项：设置 `RUN_POSTGRES_TESTS=1` 后运行 `backend/tests/test_operation_fees_postgres.py`。该测试只在随机命名的 `operation_fee_test_*` schema 内迁移和模拟并发，最后清理该 schema；测试账号需要 CREATE SCHEMA 权限。本地 Windows 环境运行该测试还需要可用的 psycopg/libpq 驱动。

`backend/tests/fixtures/operation_rows.xls` 是测试用 BIFF8 文件：Data 工作表包含标题、两行重复文本、空白行、空格行、0、返回空文本的公式、普通文本及仅格式行，预期收费行数为 5；Instructions 工作表不参与计数。

## 回滚限制

已有操作费记录时，迁移会拒绝降级到一提单一笔扣费的旧结构，避免丢失账务历史。此时应保留新结构并修复问题，不得删除操作费记录来强行降级。尚未产生操作费时可在停止写入后降级；历史税费及发票金额保持原值。
